1. Whole system: request to visible result

The frontend triggers work, the backend returns a run ID immediately, the runtime continues in the background, and Supabase is the bridge back to the UI.

2. Inside one campaign run

The graph begins with one task. Account and contact counts are discovered at runtime, so downstream tasks are added dynamically instead of being hardcoded up front.

Account Agent Find and validate real accounts

Search lithium, copper and iron ore segments. Score against the anchor. Enforce grounded URLs, LATAM operations, suppression, domain dedupe, then keep the top accounts.

→ fan out
Research Agent Build a sourced account brief

News, footprint, hazards, contractors, technology signals and a citable personalization hook.

Contact Agent Find role-fitting people

OpenAI web search + Tavily LinkedIn search. Keep sourced Operations, HSE, Site and Digital Transformation leaders.

→ both ready
Strategy Agent · deterministic gate Should we pursue this account?

Scores five explainable criteria. The LLM gathers evidence, but code owns the threshold and cannot waive missing evidence.

Evidence-gap learning loop: Strategy emits a gap ID, description, priority, owner and targeted research question → Planner adds only the necessary Research and/or Contact task → grounded findings are merged → Strategy scores the account again. Maximum one retry, so learning never becomes an unlimited credit loop.
Pursued contacts only Email Finder Agent

Known domain or Hunter domain search → Prospeo → Hunter finder → Hunter verification. Returns not_found instead of guessing.

→ email found
Writer Agent Write grounded SMYKM email

Uses only validated research and a mechanism-matched real proof point. Rotates angle, subject, transition and sender voice.

→ review
Critic Agent 11-point quality check

Checks specificity, sourcing, proof, tone, length and format. A failed draft gets exactly one rewrite anchored to the original prompt.

→ persist
persistResults + Supabase RPC Import final artifacts

Calls import_run_results, updates the run to done, and exposes the result to the polling frontend.

Cross-run feedback npm run analyze

Aggregates critic failures, rejection reasons, recurring evidence gaps, retry recovery, and unreachable-contact patterns. A human decides whether skills or policy should change.

Non-negotiable gates
No fabrication: sources must come from grounded search output or the record is discarded.
No wrong contacts: role family and name/role evidence are filtered in code.
No invented emails: only Prospeo/Hunter results are accepted.
No silent formatting drift: em dashes are stripped after generation.
No uncontrolled loops: research and rewrite retries are capped at one.
No automated sending: a human reviews and sends manually.
