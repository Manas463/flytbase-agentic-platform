FlytBase BDR Agent — How It Works

Campaign brief in (target vertical + SQM as anchor) → real accounts, contacts, research, and personalized emails out. Every box below is a real, running piece of code, not a diagram of an idea.

Campaign Brief Vertical: LATAM lithium/copper/iron-ore mining. Anchor: SQM. Angle: autonomous drone inspection replacing contracted crews.
↓
Account Agent Web-searches per commodity segment, scores every candidate against SQM (scale, hazard/24-7 ops, geography, tech adoption), drops anything unsourced or suppressed (existing customers).
↓
Research Agent Grounded web search per account: recent news, hazard/24-7 context, contracted-crew evidence, best personalization hook. Every claim sourced or left honestly blank.
Contact Agent Finds sourced decision-makers across 4 role families (Operations, HSE, Site, Digital Transformation), diversified rather than picked by rank alone.
↓
Strategy Agent — qualification gate Weighted score: ICP fit, evidence quality, operational pain, FlytBase mechanism relevance, contact readiness.
↻ if evidence is thin: one targeted extra research/contact pass, then re-score (bounded — never an unlimited loop)
↓ pursue
Email Finder Prospeo → Hunter waterfall, only ever runs on an already role-fit, sourced contact. Never invents an email — honest "not found" otherwise.
↓ email resolved
Writer Agent (SMYKM) Specific sourced hook → real FlytBase proof point, mechanism-matched to the account's own signal → one soft, low-pressure question.
↓
Critic Agent 11-point SMYKM check. Fails → exactly one rewrite pass, anchored to the same facts. Deterministic code strips em dashes and forces failures=[] when it truly passed — never trusted to the prompt alone.
↓
Persist + Feedback Loop Writes to the same production Supabase tables the live dashboard reads. A separate analytics pass aggregates real critic/strategy patterns across runs for a human to act on — never edits its own prompts.
Discovery (accounts / research / contacts) Qualification gate + retry loop Deterministic guardrail step Generation + output

How I broke the problem down

The hard constraint first. The brief's one disqualifier is fabricated data, so every stage was designed around "real source or honest gap," not around making the pipeline look complete.

Then the four required stages (Account ID → Contact Discovery → Account Research → Personalized Email), each with its own model call plus a deterministic code pass that enforces what the prompt alone couldn't be trusted to hold (em dashes, suppression matching, role-fit filtering).

Then the agentic layer on top: a Strategy Agent that's a real qualification gate (not just a ranking), a Planner that actually drives execution as a dependency graph, and a feedback loop that reports real patterns back to a human instead of auto-editing itself.

Reasoning behind the human-in-the-loop choice: this project caught the same failure twice already, a rule left purely to the model quietly stopped being followed. Letting the system rewrite its own instructions unsupervised would be that same risk, one level up.
